# 教訓を探す観点

`digest.md` と会話から手戻りを探すときの観点。どの観点で見つけたかは、行き先を決める手がかりになる。

## Navigation（必要なファイルに辿り着けたか）

- 手がかり: 同じ情報を探す `rg`・`Read`・`ls` が続いた。存在しないパス（`No such file or directory`）を何度も開こうとした。
- 行き先: CLAUDE.md・AGENTS.md から docs への参照（「何を触る前に何を読むか」）。

## Automated checks（機械で防げたか）

- 手がかり: lint・型・テスト・CI の失敗で後から見つかった誤り。ユーザーが指摘した、形で判定できる誤り（書式・禁止した API・ファイルの置き場所）。
- まずリポジトリに既にある検査（`lint` などのタスク・CI のワークフロー・hook）を読む。検査があるのに繋がっていない・壊れていることが見つかれば、それが教訓になる。
- 行き先: 既存の linter の規則、hook、CI のジョブ。

## 規約（判断を伴う指摘）

- 手がかり: ユーザーが同じ種類の指摘を繰り返した（コメントが多い・ドキュメントと重複している・責務の分け方が違う）。
- 形で判定できるなら Automated checks に回す。判断が要るものだけをここに残す。
- 行き先: CLAUDE.md、または対象を限定した docs。

## Steering files（常に読み込まれる指示が効いているか）

- 手がかり: CLAUDE.md・AGENTS.md・skill にある指示が守られなかった。指示どうしが矛盾した。
- 守られなかったときに同じ文を足しても効かない。機械で止められないか、言い回し・置き場所・skill の description の書き方を見直す。
- 禁止する形だけを並べ、代わりにどうするかが無い指示は、別の形での再試行を生む。
- 規則の置き場所と、それを強制する hook・settings.json の効く範囲（ユーザー / プロジェクト）がずれていないかを見る。
- 行き先: その指示の書き直し、または Automated checks・hook への置き換え。

## Tool economy（ツール呼び出しの無駄）

- 手がかり: Tool errors で同じエラーが繰り返されている。同じ hook に何度も止められている。巨大な出力を読み込んだ。止められたあと、別の形で何度も試した。
- hook に止められ続けるなら、hook のメッセージで正しい打ち方を伝えているか、指示に打ち方が書かれているかを見る。
- 行き先: hook のメッセージ、CLAUDE.md の打ち方の指示、settings.json の allow。

## No-ops（効いていない指示）

- 手がかり: 既定の挙動と同じことを言っているだけの指示。どのセッションにも効いた跡が無い指示。
- 行き先: 削除の提案。

## Information access（必要な情報に手が届いたか）

- 手がかり: Stops の classifier・permission-rule、sandbox による読取・書込・ネットワークの拒否、`blockReadsOutsideWorkingDirectories`。ユーザーに `!` での実行や `/add-dir` を頼んだ。
- 一時的に開けるだけで足りるもの（そのセッションだけの調査）と、毎回要るもの（いつも使うツールの設定ディレクトリなど）を分ける。後者だけを提案にする。
- 行き先: settings.json の permissions・sandbox、ツールの設定（キャッシュ先など）。

## Stops の種類ごとの読み方

| 種類 | 読み方 |
|---|---|
| hook | hook が意図どおり止めたのか、エージェントが打ち方を知らなかったのかを分ける。後者なら Tool economy |
| classifier | 止められた操作が本当に確認すべきものか。日常的な読取なら allow を、危険なら止まったままでよい |
| permission-rule | settings.json のルールが意図より広い・狭い |
| user-rejected・interrupted | ユーザーの意図とずれた。前後のプロンプトでユーザーが何を求めたかを読む |
