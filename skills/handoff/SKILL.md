# handoff

会話の経緯を知らないエージェントに、作業の続きを渡す文を書く。読み手は、渡された文だけを頼りに作業を始める。行き先によって文が残る期間と置き場所が違うので、最初に行き先を決め、行き先ごとの形で書く。

## 行き先を決める

| 行き先 | 選ぶとき | 書き方 |
|---|---|---|
| 並行するセッション（同じリポジトリ） | 今すぐ別のターミナルで続ける | 下の「貼り付ける引き継ぎ文」 |
| 別のリポジトリのセッション | 相手のリポジトリで今すぐ続ける | 下の「貼り付ける引き継ぎ文」 |
| issue（このリポジトリか別のリポジトリ） | 着手する時期が決まっていない・後で追いたい・範囲が実装計画になる | [references/issue.md](references/issue.md) |
| 設計書・仕様書 | 相手のリポジトリの `docs/` などに残す | [references/issue.md](references/issue.md) |

- 行き先が依頼に明示されていれば（「issue を立てて」「設計書を書いて」）、この表を経ずにその行に進む
- 明示されていなければ表で選び、選んだ行き先と理由を 1 行で添える。「修正しきれなかった作業を別のリポジトリに引き継ぎたい」のように、すぐ続けるとは限らない依頼は issue を候補に入れる。issue は受け取る側が `gh issue view` で読め、手元のファイルを読めるかに左右されない

完了条件: 行き先が 1 つに決まり、明示されていなかったときは理由を添えている。

## 貼り付ける引き継ぎ文

受け取る側のセッションにそのまま貼る文を、会話の中に 1 つのコードブロックで出す。ファイルには保存しない。別のリポジトリのセッションが作業ディレクトリの外のファイルを読むと、`blockReadsOutsideWorkingDirectories` を有効にした環境では確認で止まる。OS の一時ディレクトリも作業ディレクトリの外にある。利用者は `/copy` でコードブロックを取り出せる。

### 中身

次の節を、この順に、中身があるものだけ書く。

```markdown
## 目的
<!-- 何のための作業か、終わったら何ができるようになるか -->

## 今の状態
<!-- 終わったこと・決まったこと・試して駄目だったことと理由。決まったことには理由を添える -->

## 次にやること
<!-- 受け取る側が最初に手を付けること。完了と判定できる条件 -->

## 受け取る側の準備
<!-- 作業ディレクトリ・ブランチ、`/add-dir` や `!` での実行が要る手順 -->

## 参照
<!-- 着手前に読むもの。何を確かめるために読むか -->

## 使う skill
<!-- 受け取る側で呼ぶとよい skill と、何に使うか -->
```

内側にコードブロックを含むときは、外側を 4 連バッククォートで囲む。

### 参照は受け取る側から開ける形にする

既にある成果物（issue・PR・commit・設計書）は書き写さずに場所を示す。ただし、受け取る側が開ける形で示す。

- push 済みの commit・issue・PR・ファイル: URL（`https://github.com/<owner>/<repo>/blob/<commit>/<path>` など）か、`gh issue view <番号> --repo <owner>/<repo>` で示す
- 受け取る側のリポジトリのファイル: そのリポジトリのルートからの相対パス
- 同じ作業木で続けるセッション: 作業木のルートからの相対パスでよい。別の worktree には、commit していない変更は見えない
- push していない commit・diff・作業ディレクトリの外のファイル・会話の中にしか無い出力: 受け取る側からは読めない。必要な部分を本文に書き込む。push すれば URL で示せる、と報告で添えてよい（push はしない）

### skill は受け取る側で使えるものだけを挙げる

挙げるのは、ユーザースコープ（`~/.claude/skills/`）に入っている skill と、受け取る側のリポジトリの `.claude/skills/` にあると確かめた skill だけ。今のリポジトリの `.claude/skills/` にしか無い skill は、別のリポジトリでは呼べないので挙げない。確かめられなかったら、確かめられなかったと書く。

### 伏せる

API キー・トークン・パスワード・個人を特定できる情報（メールアドレス・氏名など）は書かない。必要なら「`<API キー>`」のように置き場所だけを示す。貼った文は受け取る側のセッションの transcript に残る。

完了条件: コードブロックが 1 つあり、その中の参照がすべて上の形で受け取る側から開け、挙げた skill が受け取る側で使え、秘密情報が無い。
