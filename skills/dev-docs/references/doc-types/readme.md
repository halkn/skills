# README

リポジトリやフォルダの入口になる文書。読み手は初めて来た人で、これが何か、自分に要るか、どう使い始めるかを知りたい。全文は読まず、見出しから要る節を拾う。

## 見出し

- 節の見出しは項目名にする（「インストール」「使い方」「開発」）。読み手は慣れた名前の節を探すため、よく使われる項目名に合わせる。
- 項目名は名詞か、動詞で終える短い句にする（「設定を変える」）。

## 型

```markdown
# <名前>

<これが何で、誰が何のために使うかを1〜3文で>

## 前提

- <要るツールと版、権限>

## インストール

1. <手順>

## 使い方

<最も多い使い方を1つ、コマンドと出力の例で>

## 設定

<変えられる項目。多ければ表にする>

## 開発

<手元で動かす・試験する手順。開発の決まりが別の文書にあればリンクする>
```

- 要らない節は書かない。上の順はよく使われる順で、読み手が探す順に近い。
- 既存の README の書き直しでは、節の順と項目名を保ち、中身を書き換える。項目を足すのは新しい話題のときだけにする。

## 図

- 図は補助で、構成を1枚で見せると使い方が分かるとき（複数の部品を組み合わせるツールなど）だけ入れる。
- 手順の流れは図にせず、番号付きの箇条書きにする。

## 書かないこと

- 変更の履歴。リリースノートか CHANGELOG に分ける。
- 設計の詳細。設計書へのリンクにする。
